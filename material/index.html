Clase Práctica: Todo App con React, TypeScript y Redux Toolkit 🚀

Vamos a construir una aplicación de lista de tareas desde cero, conectada a una API real, y la desplegaremos en la web.

Conceptos que Aplicaremos

  • React: Crearemos componentes reutilizables (`TodoList`, `TodoItem`) y los "compondremos" para formar nuestra aplicación.
  • TypeScript (TS): Usaremos TS para definir "contratos" (interfaces) para nuestros datos y estado.
  • Redux Toolkit (RTK): Manejaremos el estado de forma centralizada, incluyendo la lógica asíncrona para hablar con una API.
  • MockAPI: Nuestro servidor "falso" que nos permitirá hacer peticiones `GET`, `POST`, `PUT` y `DELETE` reales.
  • Bootstrap y Bootstrap Icons: Para que nuestra aplicación se vea limpia y profesional.
  • GitHub Pages: Para desplegar nuestro proyecto terminado en la web de forma gratuita.

Parte 1: ¿Qué es TypeScript y en qué se diferencia de JavaScript?

TypeScript (TS) es un **superconjunto** de JavaScript. Esto significa que es "JavaScript con superpoderes". Todo el código JavaScript válido es también código TypeScript válido, pero TS añade un componente clave: **Tipado Estático**.

Analogía: Escribir JavaScript es como construir con Legos sin instrucciones. Escribir TypeScript es como construir con los mismos Legos, pero con un manual (los "tipos") que te avisa si intentas poner una pieza donde no va.

El navegador no entiende TypeScript. Por eso, tenemos un paso de "compilación" (que Vite hace por nosotros) que transforma nuestro código .ts o .tsx en código .js normal que el navegador sí puede ejecutar.

Diferencias Clave: Tipado Dinámico vs. Tipado Estático

JavaScript (Tipado Dinámico)

Los tipos de las variables se comprueban **en tiempo de ejecución** (cuando el código ya está en el navegador). Esto puede llevar a errores inesperados que el usuario final experimenta.


// Código JavaScript Válido
function sumar(a, b) {
  return a + b;
}

// Bug silencioso: '10' + '5' = "105" (concatenación)
// No queríamos esto, pero JS lo permite.
const resultado = sumar(10, "5"); 
console.log(resultado); // Muestra "105"

TypeScript (Tipado Estático)

Los tipos se comprueban **en tiempo de desarrollo** (mientras escribes el código). Tu editor (como VS Code) te avisa de los errores *antes* de que llegues al navegador.


// Código TypeScript
function sumar(a: number, b: number): number {
  return a + b;
}

// ¡ERROR! TypeScript nos detiene aquí.
// El editor subraya "5" y dice:
// "Argument of type 'string' is not assignable to parameter of type 'number'."
const resultado = sumar(10, "5");

Herramientas Básicas de TypeScript que Usaremos

1. Tipos Primitivos

Definimos explícitamente el tipo de dato que puede contener una variable.


let nombre: string = "Ana";
let edad: number = 25;
let estaActivo: boolean = true;
let cualquierCosa: any = "Intentar evitar 'any'"; // 'any' desactiva TS

2. Tipado de Funciones

Definimos los tipos de los parámetros que recibe una función y el tipo de dato que debe retornar.


// Esta función debe recibir un 'string' y no debe devolver nada ('void')
const saludar = (nombre: string): void => {
  console.log("Hola, " + nombre);
}

3. Interfaces (El Molde o Contrato)

Una interface es la herramienta más poderosa. Define la "forma" que debe tener un objeto. Es nuestro plano o molde.


// src/types.ts
export interface Todo {
  id: string;
  text: string;
  completed: boolean;
}

// Ahora podemos usar 'Todo' como un tipo
const miTarea: Todo = {
  id: "1",
  text: "Aprender TS",
  completed: false
  // Si falta 'id' o 'text', TypeScript dará un error.
};

4. Tipar el Estado de Redux

Usamos nuestras interfaces para decirle a Redux exactamente qué forma tiene nuestro estado global.


// src/store/todosSlice.ts
import type { Todo } from '../types'; // Importamos nuestro molde

// Definimos la forma de este "slice" del estado
interface TodosState {
  items: Todo[]; // Un array de objetos 'Todo'
  status: 'idle' | 'loading' | 'succeeded' | 'failed'; // Solo puede ser uno de estos strings
  error: string | null; // Puede ser un 'string' o 'null'
}

const initialState: TodosState = {
  items: [],
  status: 'idle',
  error: null,
};

5. Hooks Tipados (La Magia)

En lugar de usar `useSelector` y `useDispatch` genéricos, creamos versiones tipadas. Esto nos da autocompletado en todo el estado de Redux.


// src/store/store.ts
import { configureStore } from '@reduxjs/toolkit';
import { TypedUseSelectorHook, useDispatch, useSelector } from 'react-redux';
// ...

export const store = configureStore({ /* ... */ });

// Inferimos los tipos del store
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

// Creamos los hooks que usaremos en la app
export const useAppDispatch: () => AppDispatch = useDispatch;
export const useAppSelector: TypedUseSelectorHook<RootState> = useSelector;

Ahora, cuando usemos `useAppSelector(state => ... )`, TypeScript sabrá que `state` tiene una propiedad `todos` (state.todos) y qué forma tiene esta.

Parte 3: Lógica Asíncrona con `createAsyncThunk`

En lugar de poner la lógica de `fetch` en los componentes, la ponemos en nuestro "slice" de Redux usando `createAsyncThunk`. Esto nos permite manejar centralizadamente los estados de carga, éxito y error.

src/store/todosSlice.ts (Ejemplo de `fetchTodos`)


// ... (importaciones y API_URL)

// 1. EL THUNK: Define la acción asíncrona "todos/fetchTodos"
export const fetchTodos = createAsyncThunk('todos/fetchTodos', async () => {
  const response = await fetch(API_URL);
  if (!response.ok) throw new Error('Error al cargar las tareas');
  const data: Todo[] = await response.json();
  return data;
});

// ... (definición del Slice) ...

  // 2. EXTRAREDUCERS: Escucha los eventos del thunk
  extraReducers: (builder) => {
    builder
      // Cuando la petición EMPIEZA
      .addCase(fetchTodos.pending, (state) => {
        state.status = 'loading';
      })
      // Cuando la petición TERMINA BIEN
      .addCase(fetchTodos.fulfilled, (state, action: PayloadAction<Todo[]>) => {
        state.status = 'succeeded';
        state.items = action.payload; // Guardamos los datos en el estado
      })
      // Cuando la petición FALLA
      .addCase(fetchTodos.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.error.message || 'Algo salió mal';
      });
      // ... (casos para addNewTodo, toggleTodo, deleteTodo) ...
  },
// ...

Luego, desde nuestro App.tsx, simplemente "despachamos" esta acción cuando el componente se carga:


// src/App.tsx
import React, { useEffect } from 'react';
import { useAppDispatch } from './store/store';
import { fetchTodos } from './store/todosSlice';
// ...

function App() {
  const dispatch = useAppDispatch();

  useEffect(() => {
    dispatch(fetchTodos());
  }, [dispatch]);
  
  // ... (resto del return)
}

src/components/TodoList.tsx (Manejo de Estados de UI)

Este componente usa useAppSelector para leer el estado de la API (status) y decide qué mostrar: un spinner, un error o la lista de tareas.


import React from 'react';
import { useAppSelector } from '../store/store';
import { TodoItem } from './TodoItem';

export const TodoList: React.FC = () => {
  // Leemos el estado completo (con autocompletado gracias a TS)
  const { items: todos, status, error } = useAppSelector((state) => state.todos);

  if (status === 'loading') {
    return (
      <div className="d-flex justify-content-center my-4">
        <div className="spinner-border" role="status">...</div>
      </div>
    );
  }

  if (status === 'failed') {
    return <div className="alert alert-danger">Error: {error}</div>;
  }

  return (
    <ul className="list-group">
      {todos.length === 0 ? (
        <li className="list-group-item text-muted">No hay tareas.</li>
      ) : (
        // Compone un 'TodoItem' por cada tarea
        todos.map((todo) => (
          <TodoItem key={todo.id} todo={todo} />
        ))
      )}
    </ul>
  );
};

Parte 5: Desplegando a GitHub Pages con Vite 🌍

Una vez que nuestra app funciona localmente, ¡vamos a publicarla en la web gratis!

Pre-requisito: Tu proyecto debe estar en un repositorio de GitHub y ya debes haber subido tu código (git push).

Paso 1: Configurar package.json

Añadimos tres cosas: la URL de nuestro sitio y dos scripts para automatizar el despliegue.


// package.json (ejemplo parcial)
{
  "name": "mi-todo-app",
  // 👇 1. Añade la URL de tu sitio
  "homepage": "https://tu-usuario-github.github.io/tu-repositorio/",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    // 👇 2. Añade este script de "pre-despliegue"
    "predeploy": "npm run build",
    // 👇 3. Añade este script de despliegue
    "deploy": "gh-pages -d dist"
  },
  // ... resto del package.json
}

Importante: Reemplaza tu-usuario-github y tu-repositorio con tus datos reales. (Ej: "https://janesmith.github.io/react-todo-app/")

Paso 2: Configurar vite.config.ts (¡Crucial!)

GitHub Pages no aloja tu app en la raíz (dominio.com), sino en una sub-carpeta (dominio.com/mi-repo/). Necesitamos decirle a Vite que use esta sub-carpeta como la ruta "base".


// vite.config.ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

// https://vitejs.dev/config/
export default defineConfig({
  plugins: [react()],
  // 👇 Añade esta línea con el nombre de tu repositorio
  base: '/tu-repositorio/', 
})

(Ej: base: '/react-todo-app/')

Paso 3: Ejecutar el Despliegue

Una vez configurado, solo tienes que ejecutar un comando en tu terminal:


npm run deploy

Este comando automáticamente:

  1. Ejecuta npm run build (gracias a `predeploy`) y crea la carpeta `dist` con tu app optimizada.
  2. Usa `gh-pages` para tomar esa carpeta `dist` y subirla a una nueva rama en GitHub llamada gh-pages.

Paso 4: Activar GitHub Pages

  1. Ve a tu repositorio en GitHub.
  2. Haz clic en "Settings" (Configuración).
  3. En el menú lateral, ve a "Pages".
  4. Bajo "Build and deployment" > "Source", selecciona "Deploy from a branch".
  5. Asegúrate de que la rama (`Branch`) esté configurada en **`gh-pages`** y la carpeta en **`/ (root)`**.
  6. Haz clic en "Save".

Después de unos minutos, tu sitio estará activo en la URL que especificaste en tu homepage.
